# Changelog

All notable changes to **Frame Africa** are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

> **How this file is maintained**
> - Add every notable change under **[Unreleased]** as you merge PRs into `dev`.
> - Group entries under: `Added`, `Changed`, `Deprecated`, `Removed`, `Fixed`, `Security`.
> - When `dev` is merged to `main` and tagged, move `[Unreleased]` items into a new versioned section with the date.
> - Entry style mirrors Conventional Commits, e.g. `feat(articles): scheduled publishing`.

---

## [Unreleased]

### Added
- **Skeleton loading across the pages we rebuilt.** Every recently-added route now shows a placeholder that matches its real layout while data loads, instead of a blank flash. New `loading.tsx` for the four multimedia hubs (videos, galleries, podcasts, interactives) and their detail pages, the video watch page, search, "For you", and topic pages, plus tailored ones for the dashboard's media library, analytics and settings. Backed by a small reusable `components/skeletons` module (hub header, media-card grid, video stage + "Up next" rail, list) so each route's loading state stays a thin, layout-accurate arrangement — theme-aware and `aria-hidden`.
- **The footer carries our social profiles, and Settings holds every key we need.** The integration catalogue was seven keys and a flat grid; it is now **grouped into nine sections** and covers the whole stack — **social profiles** (X, Facebook, Instagram, YouTube, LinkedIn, TikTok, WhatsApp), site details (public URL, contact email/phone), **email** (SMTP host/port/user/pass, from-address), **storage & CDN** (S3 bucket/region/endpoint/credentials, CDN base URL), **search** (OpenSearch URL + basic auth), **payments** (MoMo, Airtel, Stripe secret + webhook secret), **AI** (Anthropic, OpenAI), **analytics & anti-abuse** (Google Analytics, Sentry, reCAPTCHA), and **media** (YouTube). Non-secret keys now come back **in the clear with a placeholder**, so the field opens pre-filled for editing rather than forcing a retype; secrets stay write-only behind a mask. A new **public** `GET /v1/site/settings` serves only an allow-list of non-secret keys, and the **footer was rebuilt** around it: a brand + newsletter band, five link columns, and a **social rail that renders exactly the profiles that are set** (each with its real brand mark) — an unset profile simply has no icon. Social values are validated as `http(s)` URLs on write *and* on read, so nothing else can ever reach an `href`.
- **The media library is a file explorer with event albums.** Uploads were a flat pool, so an event's photos were unfindable. A new **`MediaAlbum`** (name, slug, event date, description, cover) groups the files from one shoot — **one album per file, "Unfiled" allowed** — and deleting an album **never deletes its files** (they fall back to Unfiled). It holds **every file type**, not just photos: images, video and audio in one library. Photographers own the workflow but every staff role can file into it. New endpoints for album CRUD, moving a file between albums, and `GET /cms/media?album=<id|unfiled>&kind=image|video|audio&page=`. The dashboard gains a **folder rail** (covers, event dates, counts), **file-kind tabs**, a **stats header**, **pagination**, and file cards for every type (image thumbnails, **video first-frame previews**, audio cards) each with a move-to-album dropdown. The **uploader takes many files at once** with drag & drop and a **preview tray** — thumbnail, name and size per file, removable before sending — reporting partial success honestly. (Next's 1 MB Server-Action body cap is raised to match the API's real limits: images ≤ 8 MB, audio/video ≤ 200 MB.)
- **Security events are audited and flagged to admins.** A brute-force lockout now writes `user.locked` to the audit trail (system actor, with the reason and attempt count) **and raises an in-app notification to every admin** linking to the Users page; admin `user.password_reset` and `user.unlocked` are audited too. The **audit log went advanced**: summary tiles (total / **security events** / last 24h / distinct actors), category chips with counts (All · Security · Users · Content · Other), security-tinted rows with red badges, **expandable rows** revealing the full target id and pretty-printed `meta`, and search that also matches inside `meta`.
- **The New story form is a real editor.** The headline is now a borderless hero input with a live character budget, the standfirst reads as body type beneath it, and the sidebar became iconed panels: a Publish card with a live saved/unsaved status dot and a proper error box, Details with a **premium toggle switch** (not a bare checkbox) and an excerpt counter, a Featured image panel with preview + remove and a dashed empty state, and topic chips with an "N selected" badge.
- **Full-site analytics.** The Analytics page now monitors **every interaction across every content type** — a site-wide totals row (views / likes / comments / shares), 14-day **views** and **comments** trend charts, an **interactions-by-content-type** table (articles, videos, galleries, podcasts, interactives) with a totals row, comment-moderation health, and most-viewed articles — alongside the existing realtime reading-now / referrers. `GET /v1/analytics/overview` gained the cross-content aggregates. The admin Overview's engagement tiles are now comprehensive too (real total page views + shares summed across all hubs), not article-only.
- **Our own confirmation dialogs.** Replaced every browser-native `confirm()` (10 destructive actions — delete story/comment/image/gallery/interactive/show/episode/video, reset password) with a styled, theme-aware, keyboard-accessible modal via a `ConfirmProvider` + `useConfirm()` hook.
- **Admin can reset any user's password.** The reset action now **shows the generated temporary password once** (with a copy button) so an admin can hand it over directly — matching create-new-user. The user signs in with it and is forced to set their own (`mustChangePassword`).
- **Clicking a video opens that clip.** Video cards on the homepage deep-link to `/videos/[id]`, which now renders the full YouTube-style hub (stage + "Up next" rail + grid) focused on and autoplaying the chosen clip.
- **Advanced admin Overview with live charts.** The Overview was four number tiles; it's now a real analytics dashboard. `GET /v1/admin/overview` gained a 14-day **publishing trend**, a **pipeline breakdown** (articles per workflow status), **top desks** (busiest categories), **media-library** counts (videos/galleries/episodes/interactives) and site-wide **engagement** totals (views/likes/comments/shares) — all in one batched query set. The page renders a dependency-free inline-SVG **trend chart with a hover crosshair**, ranked bar lists, media + engagement stat strips, and a recent-activity feed (latest comments + newest members). Charts are single-series/sequential with one brand accent and neutral greys — restrained by design.
- **Comments, likes and shares on every content type.** Engagement was article-only; galleries, podcast episodes, videos and data interactives had no way to react or reply. Comments are now **polymorphic** (`targetType` + `targetId`), likes moved from `article_like` to a single `content_like` table, and every type carries `likeCount` / `shareCount` — one comment table, one like table, one moderation queue for the whole site. New `GET|POST /v1/engagement/:type/:id` (like requires auth; share is anonymous and rate-limited) and `GET|POST /v1/comments/:type/:id`. On the web, a shared `ContentEngagement` (like + share + comments) now sits on the article, gallery, interactive, **podcast episode** and **video** pages — the last two are new pages (`/podcasts/[show]/[episode]`, `/videos/[id]`, backed by a new public `GET /v1/videos/:id`), so every clip and episode has somewhere its reactions can live. The moderation queue shows **what** was commented on (type badge + deep link), not just an article title.
- **Search covers the whole site.** Search was articles-only. A new `GET /v1/search/media` sweeps galleries, podcast episodes, videos and interactives (case-insensitive title/description), and the search page renders them in a **Multimedia** block below the article results — so a query with no matching article can still find the video or gallery. Every hit deep-links to the item's own page.
- **Search on every multimedia hub.** Each hub (videos, galleries, podcasts, data & interactives) now has its own search box that filters *within* that library — the four list endpoints take an optional `?q=` (title/description), the box is a plain GET form (works without JS) and searching pairs with pagination (the `Pager` preserves `q`). No results shows a clear empty state, not the "nothing published yet" hint.
- **Watch, react and discuss without leaving the video hub.** The video hub is a YouTube-style player, so like / share / comment for the clip on the stage now render **inline** and swap in place when you pick another clip from the rail or grid — comments post and refresh without a page navigation. (The standalone `/videos/[id]` page stays as the deep-link target for search and moderation.)
- **Pagination on the multimedia hubs.** Videos, galleries, podcasts and data & interactives were capped one-page lists. The four public list endpoints now take `?page=` and answer `meta.pagination.hasMore` (one extra row read, no count query), and each hub gets a shared `Pager` (prev / page / next). Past page one the hubs drop their lead item so every card is equal.

### Changed
- **Reorganised the dashboard nav into clearer sections.** The sidebar was a long **Newsroom** list (mixing personal work, the editorial queues, and the media library) plus a catch-all **Administration** group. It's now grouped by what the work *is*: **Newsroom** (Overview / My stories / New story / Analytics), **Editorial desk** (Copy desk / Review queue / Pipeline / Moderation / Tips inbox), **Media** (Media library / Studio / Videos / Galleries / Podcasts / Data & interactives), **Audience** (Inquiries / Newsletter), and **Administration** (All articles / Taxonomy / House ads / Users & roles / Monitor / Audit log / Settings). Each group only appears when the user has at least one item in it, and the gating now matches each page's own role guard.
- **Fixed mobile menus not opening / mis-scoped.** The hamburger drawers (public site + dashboard) opened but were **clipped to the header's height** — the header's `backdrop-blur` makes it the containing block for `position: fixed` children, so the full-screen drawer never covered the page. Both drawers are now **portalled to `document.body`**, so they fill the screen with the nav visible. The public mobile menu also stopped dumping the entire admin nav for staff — it now shows a clean account section (For you / My account / Newsroom dashboard / Sign out), matching the desktop profile menu.
- **Mobile responsiveness pass.** Fixed the signed-out **navbar** (brand/nav/actions pinned with `shrink-0` so the logo no longer overlaps the first section; the full section nav + search field move to `lg` with the hamburger handling `md` and below; Sign in / Subscribe trimmed to fit). On **mobile**, the article page now shows the **Most-read + newsletter** that were desktop-only (the tall half-page ad stays desktop-only, a compact native slot shows on phones), and the newsroom **stories / all-articles tables become stacked cards** instead of a cut-off horizontal-scroll table. (Users & audit admin tables still scroll horizontally on phones — a follow-up.)
- **Ad Studio + video/animation ads, and fixed ads not displaying.** Two bugs stopped house ads from showing: the "new ad" image field was a URL input that **silently rejected relative paths** (media-library `/uploads/…` and `/seed/…` images), so the form never submitted; and ad mutations only revalidated the dashboard, never the public pages. Both fixed — the image field accepts any URL/path, and create/pause/delete/publish now `revalidateTag` the ad fetch + the public layout so changes appear on the site immediately. **Video / GIF ads** are now supported end-to-end: `AdSlot` renders autoplay-muted-loop `<video>` for `.mp4/.webm` creatives (GIFs already animate), the House-ads manager takes a video URL and shows creative thumbnails, and the **Ad Studio** gains a **Video · GIF mode** (paste a hosted clip, preview at the slot size, publish) beside the static designer. Both ad pages are full-width.
- **Advanced Flyer Studio.** The Studio is now a full flyer/social-card designer: a **readability backdrop (scrim)** and **drop shadow** behind the text, **element positioning** (text top/middle/bottom, left/centre, overlay style gradient/full/none, headline scale), a **CTA pill**, five sizes (square, 4:5, story, wide, **A4 flyer**), presets, and a **designed social-media bar** — drawn Instagram / X / Facebook / YouTube / LinkedIn / WhatsApp icons with a handle. Controls are grouped into sections; exports a print-ready PNG.
- **Newsroom dashboard pages redesigned (full-width, consistent).** The **Overview** is now a whole-system dashboard for admins (a System-overview KPI row — users, published, pipeline, flagged — above personal "Your work" stats). The **Media library** gains real **CRUD** (a new `DELETE /cms/media/:id` for editors/admins) plus a redesigned grid with search, per-image copy-URL and delete, and file type/size. **Analytics** gets icon KPI cards; **Studio**, **Copy desk**, **Review queue**, **Moderation**, **Tips inbox** and **Pipeline** share the full-width header pattern with counts, cleaner cards and empty states.
- **Admin dashboard pages redesigned (full-width, advanced).** **Users & roles** and **All articles / My stories** are now management tables with **status filter tabs (counts), search, pagination and CRUD row actions** (edit/view, delete-with-confirm on admin lists). **Settings** is a modern integration **card grid** (status pills, masked value + updated date, set/update/remove) with a configured-count. **Audit log** gains actor avatars, category-toned action badges, an action filter, search and pagination. **Monitor** becomes icon **KPI cards** + iconed activity panels (avatars, status badges). **Taxonomy** is a two-column **section tree** (indented children, count pills, hover rename/delete) beside a **Topics** sidebar with search. The **new/edit story** form is a two-column CMS editor (writing column + sticky settings sidebar).
- **System-wide audit pass (design + security + completeness).** Rebuilt the **Ad Studio** into a real design tool — 5 templates, headline that **auto-fits instead of truncating**, a larger centred canvas, a media-library image picker, font/position controls and a brand accent rule. Added **helmet** security headers to the API (`X-Frame-Options`, `nosniff`, HSTS, `Referrer-Policy`) and disabled `X-Powered-By`. Widened the **dashboard shell** (to 1560px) so data pages use the screen; **fixed the pipeline kanban** clipping (columns are now bounded scroll panels); rebuilt the **analytics** page (full-width, KPI cards + a most-read bar chart). Verified RBAC + object-level authZ across every privileged endpoint.
- **Single Roboto type system.** Headlines, body and chrome now all use **Roboto** (dropping Fraunces / Inter / Source Serif) for one consistent family across the whole product.
- **Redesigned the account page.** A real profile header (avatar, role badges, 2FA status, quick actions to For You / Newsroom / Sign out), stat tiles, a two-column layout with **thumbnailed** Saved + Recently-read cards, and a sidebar for Following, security and privacy/data.
- **Signed-in profile menu.** The header now shows an **avatar button** (photo or initials monogram) that opens a dropdown: an identity header (name, email, role badge) plus **For you, My account, Saved stories, Account & security**, a **Newsroom dashboard** entry for staff, and **Sign out** — replacing the loose For-you / name / Newsroom links.
- **Auth pages: social sign-in, legal, and a shared shell.** Login and signup gain **Continue with Google / Apple** buttons (honestly marked "soon" until OAuth credentials are configured on the API), an "or continue with email" divider, and a **Terms of Use & Privacy Policy** consent line — with real **/privacy** and **/terms** pages behind it (fixing the previously-dead cookie-banner link). A two-column layout puts an **editorial pitch on the left** (logo + highlights, on the page background) beside a compact form card that fits without scrolling. The whole password flow — **forgot / reset / first-password / verify-email** — now reuses the same `AuthShell` (centered card with the logo, no side panel or social row).
- **Harmonised colour system (background ↔ text).** Retuned both theme ramps so surfaces and type sit in one warm family. Dark theme now uses **warm near-black** surfaces with **soft off-white** text (less glare) and warm-tinted greys/borders; light theme keeps the warm cream but **deepens the primary to a burnt amber** so orange kickers/links clear ~4.3:1 contrast on the cream (they were ~2.4:1). Verified contrast for text/muted/faint against the background in both themes.
- **Top-right corner accent + calmer texture.** The page background is now almost flat (the dot grid was dialled right down, especially in dark mode) and the "design" is concentrated into a **Fluent/Mica-style top-right corner flourish** — a soft brand bloom with fine concentric arcs that melt into the page before the content. The arcs are drawn in a neutral tone so they read as geometry, not a colour cast; light mode keeps the bloom soft so the page stays white. The dashboard **sidebar** now uses the secondary surface tone so it's subtly distinct from the (pure-white) content in light mode.
- **Pure-white light theme.** Light mode is now a clean **pure white** page (was a warm cream that read slightly yellow). Secondary fills use a light neutral grey, and the page/dashboard background drops the warm mesh blobs in light mode — keeping only a whisper-fine neutral dot grid. Dark mode keeps its warm mesh; the deepened burnt-amber accent is unchanged.
- **Dashboard workspace canvas + fluid width.** The newsroom content area gets its own quiet mesh (soft warm corners + a whisper-fine dot grid, a touch richer than the public page) so panels read clearly as "the content", while the sidebar stays a clean surface. The content is now **fluid width** — collapsing the sidebar actually reclaims the space instead of staying pinned to a centered column.
- **Subtle page + placeholder backgrounds (Fluent/Mica-style).** The page background gains a soft, barely-visible mesh — a few faint warm blobs plus a whisper-fine dot grid — so it no longer reads as a flat empty canvas, while never competing with the text. The no-photo `media-fill` placeholder gets the same quiet treatment (card tone + faint dot grid + a whisper of the accent in one corner) instead of the old heavy primary gradient and aperture ring. Both are theme-aware for light and dark, using only existing colour tokens.
- **Redesigned homepage hero + connected section system.** The lead's secondary column is now a **Top stories** block with a wide-image lead item and compact thumbnail rows (real hierarchy, no flat headline list). **Most read**, **Editor's picks** and **Latest** now share one **accent-tick connector** heading (`RailHeading`/`SectionHeading`) so the rail and main columns read as a single system, and the Most-read list is an advanced **01–06 ranked** list with the top three in the accent colour.
- **Single-row public masthead.** The header is now one consolidated bar — brand, section nav and actions on a single row (the separate masthead/date row is gone). It **condenses on scroll** (padding shrinks, subtle shadow), highlights the **active section** with an animated underline, and each top section opens a **mega-menu** showing its sub-sections beside the section's **latest story** with a thumbnail. Nav labels use the page font (Roboto), sized to fit the row.
- **Enhanced breaking-news bar.** Each rotating headline now leads with its **section kicker**, the flag and controls use the page font (no monospace), and the position counter is replaced by **clickable dot indicators** (plus a read arrow) that jump between stories and reset the timer. Keeps the notched pulsing **Breaking** flag, roll-up animation, live progress bar and pause-on-hover.
- **Redesigned sign-in & sign-up.** A shared `AuthShell` centers the form in a card over the site's own background — lifted only by a soft, low-opacity brand glow and a faint grid — with minimal copy and a security note.
- **New type system.** Headlines now use **Fraunces** (an elegant editorial serif) for a premium newspaper feel, the UI/chrome uses **Inter** (clean, legible sans), and article body keeps **Source Serif** for reading. The heading font is decoupled from the base UI font (distinct `--font-*` tokens).
- **Newsroom story management + editor redesign.** The **New/Edit story** form is now a real two-column CMS editor — a wide writing column (large headline, standfirst, body) beside a sticky settings sidebar (Publish, Details, Featured image with preview, Topics). **My stories** and the admin **All articles** page are rebuilt as a shared management **table** with **status filter tabs (with counts)**, **search**, **pagination** (12/page), and per-row actions — Edit / View, plus **Delete** (with confirm) on the admin articles list. All pages fill the dashboard width.

### Added
- **Data & interactives — embeddable charts / graphics (Multimedia WS4).** The final multimedia type: staff embed a data visualisation or interactive graphic by pasting a URL, which is **validated against an allow-list of trusted providers** (Datawrapper, Flourish, Infogram, Google Data Studio/Looker/Sheets, YouTube — YouTube normalised to a nocookie embed) and rendered in a **sandboxed iframe** — anything off the list is rejected, so a staffer can never embed an arbitrary hostile page. Managed at **`/dashboard/interactives`** (editor/admin: title, embed URL, description, source, aspect ratio, cover, draft→publish, live preview); readers get an **`/interactives`** hub and **`/interactives/[slug]`** detail. Added to the Multimedia nav (desktop + mobile subnav, footer, dashboard). New API: public `GET /interactives` (+ `/:slug`), staff `GET/POST/PATCH/DELETE /admin/interactives`. New `Interactive` model + `InteractiveProvider` enum. Unit-tested (incl. allow-list bypass attempts) + verified e2e.
- **Podcasts (audio *or* video) + audio/video uploads + Multimedia nav (WS3).** A full podcast content type: **shows** (with RSS/Spotify/Apple subscribe links) grouping **episodes**, where each episode is **audio or video** and its media can be **uploaded or linked** — an uploaded file, an external audio URL, or a video/YouTube link. Editors manage them at **`/dashboard/podcasts`** (show editor with an inline episodes manager: add, publish/unpublish, delete; audio/video toggle; paste-URL-or-upload); readers get a **`/podcasts`** hub and **`/podcasts/[slug]`** show page with the right player per episode (audio element, self-hosted `<video>`, or click-to-play YouTube). To support uploads the media library now accepts **audio/video** (`POST /cms/media/av`, MP3/M4A/AAC/OGG/WAV or MP4/WebM, up to 200 MB). The public **Multimedia** nav now has a real **subnav** (Videos · Photo galleries · Podcasts) on desktop and mobile — and no longer renders "Multimedia" twice. New API: public `GET /podcasts` (+ `/:slug`), staff `GET/POST/PATCH/DELETE /admin/podcasts` and `.../episodes`. New `PodcastShow`/`PodcastEpisode` models + `PodcastMediaKind` enum. Unit-tested + verified e2e.
- **Photo galleries — a standalone visual-story type (Multimedia WS2).** Galleries are now first-class content, not just an inline article block. Photographers/editors/admins build them at **`/dashboard/galleries`**: a card list + a two-column **editor** (title, description, cover, and an ordered photo list — each with URL, alt, credit, caption, reorder, remove — drawn from media-library URLs), with **draft → publish** and delete. Readers get a **`/galleries`** hub and a **`/galleries/[slug]`** detail page with a **full-screen lightbox** (keyboard ←/→/Esc, prev/next, counter). New API: public `GET /galleries` + `GET /galleries/:slug`, and `GET/POST/PATCH/DELETE /admin/galleries` (photographer/editor/admin); image URLs + text are sanitised on write (reuses the article block sanitizer). New `Gallery` model + `MediaStatus` enum. Unit-tested + verified e2e.
- **Videos management dashboard + curation (Multimedia WS1).** The YouTube hub is now editor-managed, not sync-only. A new **Videos** page (`/dashboard/videos`, a new **Multimedia** nav section) lets editors/admins **sync the channel**, **add a clip by URL** (paste any YouTube watch/`youtu.be`/shorts/embed link — the id is extracted, metadata fetched when an API key is set, else a title is supplied and a deterministic thumbnail used), **feature** a clip to pin it to the top of the hub + homepage strip, **hide** a synced clip from the public hub without deleting, and **delete**. New API: `GET /admin/videos`, `POST /admin/videos`, `PATCH /admin/videos/:id`, `DELETE /admin/videos/:id` (editor/admin) alongside the existing `POST /admin/videos/sync`; the public hub now serves visible clips **featured-first**. Unit-tested + verified e2e.
- **Footer that works, reader→newsroom inbox, and admin newsletter send.** Every footer link now points at a **real page** (Company → About / Advertise / Contact / Send a tip; Read → Latest / For you / Videos / Search; Legal → Privacy / Terms / Editorial standards / Corrections) — no more dead labels. New public **/about**, **/advertise** and **/contact** pages carry forms that a reader fills in; submissions post to a rate-limited public `POST /v1/inquiries` and land in a new admin **Inquiries** inbox (`/dashboard/inquiries`, admin-only) with type tabs (All / New / Advertising / Contact / Closed), status workflow (New → In progress → Closed) and a mailto reply. Editors/admins get a **Newsletter** composer (`/dashboard/newsletter`) that sends a campaign to active subscribers (`POST /v1/newsletter/campaigns`, records recipients + history) beside a live subscriber count.
- **Notifications for everything the newsroom receives.** The dashboard bell now fires on inbound activity, not just your own stories: a new **advertising/contact enquiry** alerts admins, a **confidential tip** alerts editors + admins, a **new newsletter subscriber** alerts admins, and a **reported comment** alerts moderators + editors + admins (once, when it first gets flagged, so a pile-on doesn't flood the bell). Each notification deep-links to the desk that handles it. Fan-out is best-effort — emitting an alert can never break the action that triggered it. Unit-tested.
- **Slimmer homepage hero.** The front-page lead's photo was oversized — tall enough to push the headline out of view. The featured card now uses a **2∶1 image** with a **smaller headline/excerpt**, so the story title reads right beside/under the photo within the fold.
- **Full-width article reading layout.** The story page no longer sits in a narrow centered column with empty margins — it's now a **three-zone layout** that fills the page: a sticky **vertical share rail** on the left, the reading column (left-aligned, capped for readability), and a sticky **right sidebar** (Most-read, newsletter, half-page ad) that fills the right. Type and the hero image were **scaled down** (slimmer 21∶9 hero, smaller headline/body) so stories read tighter and shorter.
- **Edit your profile.** Readers can now change their **display name and avatar** from the account page: an "Edit profile" modal with a **live avatar preview**, backed by a new authenticated `PATCH /v1/me` endpoint (validates name length and requires an http(s) avatar URL, or blank to clear). The account page and header update immediately via revalidation.
- **Metered paywall + subscriber unlock (WS10).** Readers get **N free articles per month** per device (opaque `fa_reader` cookie, no PII); past the meter a story returns the existing `402` preview. Re-reading a story you already opened is free, and crawlers (no reader key) are never metered. A **subscriber** (`user.subscribedUntil`) bypasses both the meter and premium locks — granted/revoked by an admin (`PATCH /v1/admin/users/:id/subscription`, audited) until self-serve MoMo/Airtel payments land. **Disabled by default** (`PAYWALL_FREE_ARTICLES` unset) so nothing locks until you turn it on. Unit-tested + verified e2e.
- **Ad Studio (WS9).** A canvas designer at `/dashboard/ads/studio` for building ad creatives at the exact **IAB sizes** (leaderboard 970×90, billboard 970×250, rectangle 300×250, half-page 300×600, native 1200×675): headline/subline/CTA, brand colours + swatches, background photo with adjustable darkening, and the Frame Africa mark. Export a **PNG**, or **publish straight into a live slot** — the creative uploads to the media library and becomes a serving house ad in one click.
- **YouTube video hub (WS8).** Channel uploads now sync automatically into a local cache (hourly in-process job + admin `POST /v1/admin/videos/sync`), driven by `YOUTUBE_API_KEY` + `YOUTUBE_CHANNEL_ID` from **admin settings**. New `/videos` hub and a real homepage **Watch** strip render from the cache with **click-to-play `youtube-nocookie`** embeds (no third-party iframe loads on page view). Degrades to a clean empty state until a channel is connected. Unit-tested + verified e2e.
- **Managed house ads (WS9).** Ad slots now serve **admin-managed creatives** instead of a hardcoded placeholder: `house_ad` model + `/dashboard/ads` CRUD (create, pause/activate, delete), public `GET /v1/ads?placement=` serving into the labelled IAB slots with a house fallback, and click-through `GET /v1/ads/:id/go` (302) with **impression + click counting**. The full ad-sales/targeting server remains. Unit-tested + verified e2e.
- **Newsletter subscribe / unsubscribe (WS11).** The homepage signup box now really subscribes (`POST /v1/newsletter/subscribe`, rate-limited, dedup/resubscribe) with one-click token **unsubscribe** (`/unsubscribe`) and an editor subscriber count. Digest **delivery** (SMTP/queue) + open/click analytics remain. Unit-tested + verified e2e.

### Security
- **Brute-force account lockout.** After **5 consecutive failed sign-ins** an account is locked (`failedLoginAttempts` + `lockedAt`) and rejects login — even with the correct password — until an **admin unlocks it** (`POST /v1/admin/users/:id/unlock`; a "Locked" badge + Unlock button in the Users table). A successful sign-in resets the counter.
- Established security design baseline (`documents/05-Security-Design.md`) and vulnerability-reporting policy (`SECURITY.md`).
- `GET /v1/articles/:slug` no longer leaks the full body of premium (`isPremium`) articles to unsubscribed callers: it now returns a one-paragraph preview with `isLocked: true` and HTTP `402`, per `04-API-Design.md` §7.
- Passwords hashed with **Argon2id**; refresh tokens stored **hashed** and delivered in an **httpOnly, SameSite=strict** cookie with **rotation + reuse detection** (replaying a rotated token revokes the whole token family), per `05-Security-Design.md` §3.
