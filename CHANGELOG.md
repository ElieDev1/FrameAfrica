# Changelog

All notable changes to **Frame Africa** are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

> **How this file is maintained**
> - Add every notable change under **[Unreleased]** as you merge PRs into `dev`.
> - Group entries under: `Added`, `Changed`, `Deprecated`, `Removed`, `Fixed`, `Security`.
> - When `dev` is merged to `main` and tagged, move `[Unreleased]` items into a new versioned section with the date.
> - Entry style mirrors Conventional Commits, e.g. `feat(articles): scheduled publishing`.

## [Unreleased]

### Changed
- **Redesigned public masthead.** A cleaner two-row header: the top row carries the brand (left), the live **date · Kigali** (centered) and an expanding **search** field, theme toggle and account/subscribe or staff menu (right); a single centered **section nav** sits below. Dropdown indicators and "View all" links now use **real SVG chevron icons** (no glyphs), and mega-menu sub-links use the UI sans for a crisper read.
- **Live breaking-news ticker.** The breaking strip is now a notched, broadcast-style **Breaking** flag with a pulsing live dot and a **single-line vertical rotator**: one headline at a time rolls up from the bottom every few seconds, with a thin progress bar and an `03 / 10` position counter. Pauses on hover and honours `prefers-reduced-motion` (was a static horizontal-scroll list).
- **New type system.** Headlines now use **Fraunces** (an elegant editorial serif) for a premium newspaper feel, the UI/chrome uses **Inter** (clean, legible sans), and article body keeps **Source Serif** for reading. The heading font is decoupled from the base UI font (distinct `--font-*` tokens).

### Added
- **Real full-text search (WS12).** The search page now runs on a dedicated `GET /v1/search` powered by **PostgreSQL full-text search** — weighted relevance (title ≫ subtitle ≫ excerpt ≫ body via `ts_rank`), `websearch_to_tsquery` (so `"quoted phrases"` and `-exclusions` work), and **highlighted snippets** rendered safely as `<mark>` (no `dangerouslySetInnerHTML`). Adds `GET /v1/search/suggest` prefix autocomplete and a language filter. This replaces the interim `LIKE` scan; **OpenSearch** is now a drop-in scale swap behind the same endpoint (a GIN index is the local perf step). Unit-tested and verified e2e.
- **In-app notifications (WS11).** The dashboard bell is now real: an unread badge (60s poll), a dropdown that lists notifications newest-first, mark-one/mark-all-read, and deep links to the story or draft. The newsroom emits them automatically — when an editor **publishes** a story its author is told it's live, and when a story is **returned** for changes (editor reject or copy-desk return) the author gets the note. New API: `GET /v1/me/notifications`, `GET …/unread-count`, `POST …/:id/read`, `POST …/read-all`. Emitting is best-effort (never blocks the triggering action). Unit-tested and verified e2e. _(Reader comment-reply alerts and web push land with a reader bell / WS16.)_
- **Personalised "For You" feed (WS14).** Signed-in readers get a `/for-you` page (and a header link) with a feed built from the sections and topics they **follow** plus the sections they **read** most — following a parent section surfaces its sub-sections too. With no signal yet it degrades gracefully to the latest news and invites the reader to follow things. New API: `GET /v1/me/feed` (auth, cursor-paginated, `meta.personalized`). Unit-tested and verified e2e (following a parent section returned its sub-section stories).
- **Follow sections & topics + reading history (WS7).** Signed-in readers can **Follow / Unfollow** any section or topic (a real-icon toggle on the section & topic pages), and their **reading history** is recorded as they read. The account page gains a **Following** list (with inline unfollow) and a **Recently read** list (with one-tap **Clear** for privacy). New API: `GET/POST/DELETE /v1/me/follows/:target/:id`, `GET /v1/me/follows`, plus `POST /v1/me/history/:id` and `GET/DELETE /v1/me/history` — all published-only, idempotent, and unit-tested. These follows + history are the signals for the personalised "For You" feed (WS14).
- **Redesigned dashboard shell.** A proper newsroom app shell: a richer top bar with a brand, admin **search**, a **"New story"** quick-create, **notifications** bell, theme toggle, and a **profile menu** (account / view site / sign out); a **collapsible** sidebar (full ↔ icons-only, remembered) whose logo + toggle sit in a fixed header aligned with the top bar (they read as one strip) while only the nav scrolls; **real SVG icons** on every nav item; **collapsible nav groups**; and a working **mobile drawer** (the dashboard previously had no navigation on mobile). Content sits in a centered max-width column.

### Fixed
- **Slimmer scrollbars app-wide, and none on the dashboard sidebar.** Global thin scrollbars (Firefox + WebKit) with a `no-scrollbar` opt-out applied to the dashboard sidebar/drawer, which still scroll when needed but show no bar.
- **Public navbar/footer no longer leak onto the dashboard (and no longer flicker).** Public pages now live in an `app/(site)/` route group whose layout owns the `SiteHeader`/`SiteFooter`; the dashboard sits outside the group with its own shell. Previously the chrome was rendered in the shared root layout and gated by a request-header check, which persisted across client-side navigation — so whether it showed depended on which page you hard-loaded first. Crossing the group boundary now mounts/unmounts the chrome correctly.

### Changed
- **Staff 2FA is now opt-in, not forced.** The dashboard no longer forces staff to enrol in two-factor before entering the newsroom. The full 2FA feature stays in place — users can enable it at `/account/security` and login still requires a code when it's on — and mandatory enrolment can be switched back on any time by setting `ENFORCE_STAFF_2FA=true`.

### Added
- **Seed: second admin + a large article corpus (~320).** Added a second admin (`newsroom.admin@frameafrica.rw`), 20 hand-written flagship stories, plus a **deterministic generator** that fills **every category** with well-detailed multi-block articles (~300 total) — for exercising pagination/"load more", section aggregation, Most-read, and the premium paywall. Generated content is stable across re-seeds (idempotent), varies by subject/angle/place, and sprinkles breaking/premium/featured flags; cover-less stories use the branded placeholder.

The **homepage** was rebuilt for wide screens (~1440px): a stronger hero, a 3-column "Latest" river with `SectionHeading` connectors, full-width **section bands**, and a sticky rail; **ads** gained IAB units (billboard, half-page sticky, in-feed native) alongside the leaderboard. The **article page** and **comments** were polished (breadcrumb/related use icon connectors, read-time clock icon, comment avatars + icon actions).
- **Reader UI overhaul — real SVG icons (WS17, phase 1):** a dependency-free, CSP-safe inline **SVG icon set** (`components/icons`) — UI icons (heart, bookmark, share, comment, flag, trend arrows, play…), WMO-mapped **weather icons**, and brand marks (X, Facebook, WhatsApp, LinkedIn). Replaced every emoji/glyph in the reader UI: like buttons and comment likes now use real heart icons, comment report uses a flag, the share bars use real brand-logo buttons (+LinkedIn & email), and the video strip uses a play icon.
- **Moderator user bans (WS16):** moderators/editors/admins can **ban a user from commenting** (and unban) straight from the moderation queue. A banned user can still read but gets a 403 when posting a comment; the queue shows a "banned" badge and a Ban/Unban toggle per author. Distinct from an admin account suspension (a comment ban keeps read/login access). Adds a `comments_banned_at` field and `POST /cms/users/:id/{ban,unban}`; completes the moderator role.
- **Editor scheduling, embargo & archive (WS15):** editors can now **schedule/embargo** a reviewed article to go live at a future time (review queue → pick a date/time) — it holds as `embargoed` (shown as "Scheduled") and an in-process publisher promotes it to `published` when due, so it stays hidden from public reads until then. Editors can also **publish now** a scheduled item and **archive** a published story (removes it from the public site, keeps it in the newsroom). New API: `POST /cms/articles/:id/{schedule,archive}` plus a `SchedulerService` that publishes due articles every minute. Completes `07 §UC-04` (`FR-EDIT-2`, `-3`).
- **Sub-editor copy desk (WS14):** the sub-editor role now has a real workflow. A submitted draft lands on the **copy desk** (`copy_edit`) instead of going straight to editors; a sub-editor (or editor/admin) polishes the copy at `/dashboard/copydesk`, then **passes it to the editors' review queue** (`ready`) or **returns it to the writer** with a note. New API: `GET /cms/copydesk`, `GET/PATCH /cms/copydesk/:id`, `POST /cms/copydesk/:id/{pass,return}`. The newsroom pipeline is now draft → copy-edit → review → published. Dashboard nav is now **capability-based** off the user's roles (so sub-editors and moderators get their own desks), and sub-editor/photographer/moderator/ads-manager accounts can now reach the dashboard.
- **Admin full CRUD — god-mode over the whole system (WS13):** the admin no longer just mirrors the journalist/editor flow. **Articles:** create-and-publish directly, edit any, **publish / unpublish / archive**, **soft-delete → Trash → restore** — all bypassing the review workflow (`/dashboard/articles` + edit page). **Taxonomy:** full CRUD for **sections/sub-sections and topics** at `/dashboard/taxonomy` (create, rename, re-parent, delete — with in-use guards so a section with sub-sections or articles can't be deleted). **Comments:** moderators/admins can now **delete** a comment outright from the moderation queue. New admin API: `POST/DELETE /cms/admin/articles[/:id][/publish|unpublish|archive|restore]`, `GET /cms/admin/articles/trash`, `GET/POST/PATCH/DELETE /admin/taxonomy/{categories,topics}`, `DELETE /cms/comments/:id`.
- **Security & trust — 2FA + real email (WS12):** staff accounts can (and must) enable **TOTP two-factor authentication** — a `/account/security` page with a QR code + manual key to enrol an authenticator app, and login now prompts for a 6-digit code when 2FA is on (the API signals the 2FA step distinctly from bad credentials). 2FA is **mandatory for staff**: the dashboard redirects any staff member without it to enrol first (`FR-AUTH-6`, `05` §3.3). TOTP is implemented natively (RFC 6238, verified against the RFC test vector). Separately, **transactional email now sends for real** via SMTP (nodemailer) when `SMTP_*` is configured — verification, password-reset, and admin-issued temporary-password emails now deliver HTML mail instead of only logging (with a console fallback in dev). New API: `POST /auth/2fa/setup|enable|disable` and an optional `token` on login.
- **Site-wide staff navigation (WS11):** signed-in staff now get a **Newsroom** dropdown in the public site header (and a matching section in the mobile menu) with role-aware shortcuts — Dashboard, My stories, New story, Studio, Media, plus Review queue & Moderation for editors and Monitor/All articles/Users/Settings for admins — so the newsroom tools are reachable from anywhere on the site, not only inside `/dashboard`. Replaces the ad-hoc "Write"/"Review" links.
- **Admin monitoring + edit-any-news (WS10):** a **Monitor** dashboard gives admins a live system snapshot — user counts (active/suspended/new-this-week), article counts (published/in-pipeline), visible vs. flagged comments, and recent-activity feeds (latest articles, comments, signups). A new **All articles** view lists every article regardless of author or status, and admins can **open and edit any of them — including published stories** — with each save recording a revision attributed to the admin. New admin-gated API: `GET /admin/overview` and `GET/GET:id/PATCH:id /cms/admin/articles`.
- **Admin integrations & API keys (WS9):** a real **Settings** dashboard where admins configure integration keys (YouTube, Anthropic/OpenAI, MoMo/Airtel/Stripe, plus any custom `UPPER_SNAKE_CASE` key). Values are stored in a new `app_setting` table and **never returned in full** — the API only surfaces a masked hint (`••••1234`) and whether a value is set (and whether it comes from the DB or an env var). A DB value overrides the matching environment variable; services read the raw value server-side via `AdminSettingsService.getValue`. New admin-gated API: `GET/PUT/DELETE /admin/settings/integrations[/:key]`.
- **Admin user management + generated-password flow (WS8):** admins get a real **Users & roles** dashboard — create accounts, assign/revoke any role, suspend/reactivate, and reset passwords. New accounts are created with a **generated temporary password** (returned once to the admin to hand over); the user is forced to set their own password at first sign-in via `/first-password` — **no email code required**. Admin-triggered resets generate a fresh password and **email it** to the user. New API: `GET/POST /admin/users`, `PATCH /admin/users/:id/roles`, `PATCH /admin/users/:id/status`, `POST /admin/users/:id/reset-password` (admin-gated), plus `POST /auth/password/first` (authenticated) and a `mustChangePassword` flag surfaced on login/`/me`. All mutations flow through the web BFF; passwords are Argon2id-hashed and never returned except the one-time generated value.

Editors, moderators, and admins get a **Moderation queue** (`/dashboard/moderation`) listing reported and pending comments with **Keep / Hide / Remove** actions; hidden or removed comments drop out of the public thread. Export to PNG still works (the upload is local, so the canvas isn't tainted). "Prefill from an article" is the remaining follow-up.

New `bookmark` table (one per user per article) + migration; authenticated `POST` / `DELETE` / `GET /v1/me/bookmarks/:id` (idempotent) and `GET /v1/me/bookmarks` (the saved list). The article page gets a **Save** button (optimistic; signed-out → login), and `/account` shows a **"Saved stories"** list. Verified e2e (save → idempotent → listed → unsave → 401 for anon).

A client canvas editor with **brand templates** (Headline · Breaking · Quote), size presets (Square 1:1 · Story 9:16 · Wide 16:9), editable kicker/headline/source, the Frame Africa aperture mark + brand colours, and **"Download PNG"**. A new `article_like` table (one per user per article, deduped) + migration; `POST` / `DELETE` / `GET /v1/articles/:id/like` (authenticated) that keep the denormalised `like_count` accurate inside a transaction (liking twice doesn't double-count). The article page gets an **optimistic like button** (♥ with the live count); signed-out readers see the count and a prompt to sign in. New `is_featured` + `featured_at` on `article`; an editor-only `POST /v1/cms/articles/:id/feature` (published-only) and a `?featured=` filter on `GET /v1/articles` (newest pin first); `isFeatured` on article payloads. - **Review desk — return with a note (WS4):** when an editor returns a submitted draft, they can attach a **note** explaining what to fix. Verified end-to-end (upload → 201 → catalogued → listed → on disk). The library UI + a picker wired into the block editor are the next increment.
- **Load-more on section & topic pages (WS2):** section and topic story rivers now start with a first page of 12 and grow via a **"Load more stories"** button (cursor-paginated, through a server action) with loading + error states — no more hard 24-story cap. Draft payloads carry their `topics`. Verified end-to-end (a draft created with `climate, exports` reads back tagged with both).
- **Topics / tags (WS2):** articles can now be tagged with **topics** — followable subjects (e.g. _Specialty coffee_, _AfCFTA_, _Amavubi_, _Monetary policy_, _Climate_) that cut across the section taxonomy (`14` §5.2). New `topic` + `article_topic` tables and migration; the read API serves an article's `topics`, exposes `GET /v1/topics/:slug`, and accepts a `?topic=` filter on `GET /v1/articles`. The web app gains **topic pages** (`/topic/[slug]` — masthead, description, story river) and **tag chips** on the article page that link through; the seed tags the demo stories. Verified end-to-end. Following a topic and CMS topic-authoring are the follow-ups.
- **Real taxonomy — nested sections (WS2, first increment):** the seeded taxonomy is now a **real nested tree** (`documents/14 §5`) — five sections (Rwanda, Africa, Business, Technology, Sport) each with sub-sections (e.g. Business › Economy/Markets/Companies, Sport › Football/Athletics/Cycling) — replacing the flat placeholders. **A section now aggregates its sub-sections:** `GET /articles?category=business` matches articles in the section *and* all descendants (descendant-aware id filter), so a top section is never empty. `GET /categories/:slug` returns the section's `parent` + active `children`, and section pages render **sub-section chips** and a parent **breadcrumb**. Verified e2e (a Football story surfaces under Sport). Topic/tag model, follow, load-more, and the admin taxonomy manager remain.
- **CMS block editor (WS1 complete):** the newsroom draft editor is now a **structured block editor** instead of a plain textarea — authors add, edit, **reorder (↑/↓), and remove** any of the ten block types (paragraph + lede toggle, H2/H3 subhead, image with alt/caption/credit, multi-photo gallery, pull-quote, source quote, bullet/numbered list, fact-box, YouTube video, divider). The document serialises to a hidden JSON field the draft form submits; the API sanitises + validates every block on write, and empty blocks are pruned client-side so a new draft never trips validation. Legacy plain-body drafts open pre-filled as paragraph blocks. **Verified end-to-end:** creating a draft via the CMS API with blocks strips markup, resolves the YouTube embed to `youtube-nocookie`, and the article renders the document. This closes **WS1 — the structured article keystone** (`documents/15`).
- **Article reading aids (WS1, web):** a slim **reading-progress bar** that fills as you scroll, a **sticky mobile share bar** (X · WhatsApp · Facebook · copy) that appears once you're into the story on phones, and an **"Updated" timestamp** in the byline for stories genuinely revised after publishing (>5 min later). Subhead anchor links already ship in the renderer.
- **Structured article — seed content (WS1):** the dev seed now writes real **block documents** instead of a plain body. The flagship story ("Rwanda coffee exports…") ships a fully structured document — lede, subheads, an inline captioned+credited photo, a pull-quote, a bulleted list, and a fact-box — and the other seeded stories get a solid generic block document; the plain `body` is derived from the blocks (mirroring the CMS write path). Verified end-to-end: `GET /v1/articles/:slug` returns the 10-block document and the article page renders it.
- **Structured article — reader rendering (WS1, web):** the article page now renders the structured document via a new **`BlockRenderer`** with purpose-built, brand-styled components for every block — lede/paragraphs, `<h2>/<h3>` subheads (with linkable anchor ids), inline captioned+credited photos, two-column galleries, pull-quotes, source blockquotes, bullet/numbered lists, a "context" fact-box, safe **YouTube (`youtube-nocookie`) embeds**, and section dividers — replacing the old plain `body.split('\n\n')`. All text is output-encoded by React (no `dangerouslySetInnerHTML`). Image URLs may be same-origin root-relative or absolute http(s).
- **Structured article — block content model (WS1 keystone, backend):** an article body is now an ordered list of typed **blocks** (`paragraph, heading, image, gallery, pullquote, blockquote, list, factbox, embed, divider`) instead of a plain string (`13` §2). A new nullable `article.blocks` JSON column stores the document; the legacy `body` is kept and **derived** from the blocks (for excerpt/search/read-time) so nothing else breaks. Author payloads pass through `sanitizeBlocks` on write — **HTML tags + control characters are stripped from all text, URLs are allow-listed to http(s)** (rejecting `javascript:`/`data:`), **YouTube embeds resolve to privacy-friendly `youtube-nocookie` URLs**, and sizes/counts are capped, throwing a `BadRequest` that names the offending block (`05` §6). The read API serves `blocks` on every article (pre-block stories are converted from `body` on the fly; premium stories expose a preview only). The CMS create/update endpoints accept and validate `blocks`. Covered by 25 unit tests (sanitiser XSS/URL/YouTube/bounds + transforms + service wiring). Web renderer + block editor are the next increments.
- **Build Tracker (`documents/15`):** a single **start→finish build checklist** that supersedes the "MVP slice" framing for execution. It defines one **Definition of Done** applied to every checkbox (real backend+frontend, all states, responsive+accessible, secure, tested, documented, committed per change) and lays out **20 ordered workstreams** — beginning with the keystone **structured article (block content model)**, then taxonomy, media library, editorial desk, live coverage, Studio, engagement, YouTube video, advertising, monetization, notifications, search, dashboard UX, personalization, i18n, PWA, trust & safety, analytics, security hardening, and a continuous quality gate.

Bodies are stored as **plain text — HTML is stripped on write** so no markup/script can be persisted (`05` §6), and React output-encodes on render. The article page gains a **comment thread + form** (or a sign-in prompt), with a couple of seeded comments. Likes/reports and the moderation queue are follow-ups.
